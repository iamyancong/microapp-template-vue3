# 0002. Chrome 90 与低配终端最低支持基线决策

## 状态

已接受 (Accepted) — 2026-09

## 背景

业务微应用运行环境主要位于金融云内，终端环境普遍为 8GB 内存机器，且浏览器版本固定在 Chrome 90 无法自主升级。早期构建配置未加限制，现代 JS 语法特性与体积过大的 bundle 经常导致旧版 V8 解释器卡顿、内存溢出与首屏长时间白屏。

## 决策

1. **构建目标统一**：生产构建的编译目标统一锁定为 `target: 'chrome90'`。
2. **轻量定向补丁**：不全量引入庞大的 core-js，仅通过 `packages/src/polyfills/chrome90.ts` 定向打补丁补齐 Chrome 90 缺失的运行环境方法。
3. **样式与色彩兼容**：避免在 Less/CSS 中使用低版本不支持的现代特性（如 `color-mix()`），主题变量统一注入 RGB 通道通过 `rgba(var(--primary-color-rgb), 0.1)` 动态派生。
4. **有界页面缓存**：`App.vue` 和 `layout/MainLayout.vue` 的 `<keep-alive>` 必须统一设置设备感知的最大缓存上限，杜绝无限制页面堆积。
5. **产物双压缩**：所有构建流均生成 `.gz` 与 `.br` 预压缩包，部署端支持静态协商返回。

## 影响

- 保障了云内旧版环境的极致稳定性与流畅度。
- 当未来基线整体升级时，只需统一调整本 ADR、`vite.config.ts` target 及 `chrome90.ts` 补丁，不得为了追求新语法随意推翻基线链路。
